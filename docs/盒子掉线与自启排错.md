# 盒子从局域网“消失”与重启后不自启：排查手册

> 这是本项目实测踩过的坑，2026-11 在小米盒子 4S Pro（Android 9 / armv7）上真实发生并修复。
> 现象很像“HA 挂了”，但根因通常在 **Wi-Fi / 路由器** 和 **开机自启**，不在 HA 代码。

## 0. 一分钟判断

| 现象 | 最可能原因 |
|---|---|
| 网页显示“连接中断，正在重新连接”，8123/8022 都打不开 | 盒子网络断了（见第 1 节） |
| 路由器终端列表里**找不到**盒子 | 盒子 Wi-Fi 断开/连到别的网段 |
| 路由器列表里**能看到**盒子，但访问不了 | Wi-Fi“假在线”（接口 UP、有 IP、但到网关不通） |
| 盒子重启后 HA 一直不来，手动开 Termux 就好 | Termux:Boot 没触发（第 1.4 节） |
| 重启后 ADB(5555) 连不上但 SSH 能用 | 正常：ADB 重启即失效 |

## 1. 根因（按概率）

### 1.1 多网关 / 多 AP 使用**同一个 WiFi 名**（最常见）

家里有两台路由器/光猫（例如两台天翼网关），WiFi 名和密码完全一样：
- 设备可能连到任意一台，**看起来同名但不是同一个网络**；
- 若其中一台是 NAT/双 DHCP，或 Mesh/中继的上联断了，设备就会“假在线”；
- Android TV 的 Wi-Fi 状态机**不会自愈**，表现为：`wlan0` UP、有 IP、但 `ping 网关` 报 `Destination Host Unreachable`。

**典型真实输出：**
```
$ ping -c 2 192.168.1.1
From 192.168.1.69: icmp_seq=1 Destination Host Unreachable
100% packet loss
$ getprop dhcp.wlan0.gateway     # 空
$ ifconfig wlan0                 # UP, inet 192.168.1.69
```

### 1.2 盒子 Wi-Fi 配置残留

换过路由器/改过密码/换过节点后，盒子里的旧配置可能导致它连在“错误的地方”。**修复：忽略该网络 → 重新输入密码连接**（实测最有效，一步恢复）。

### 1.3 双 DHCP / 同网段双 NAT

两台网关都用 `192.168.1.1`、都在发 DHCP → 设备拿到同网段但不同广播域的 IP，互相访问时通时断。
排查：两台网关后台看 DHCP 是否都开启；只保留一台发 DHCP。

### 1.4 重启后 Termux:Boot 没触发

- Termux:Boot 会执行 `~/.termux/boot/` 下的脚本（我们的 `start-ha.sh` 负责拉起 HA/SSH）；
- 部分电视盒子会限制第三方自启动（尤其“快速启动/待机”模式下不会发开机广播）；
- 表现：重启后 8123/8022 都不在，手动打开 Termux 执行 `sv up hass` 就恢复。
- 验证：看 `~/boot.log` 里有没有本次开机的 `boot hook fired` 记录。

### 1.5 ADB 5555 重启即失效（正常）

`adb tcpip 5555` 是临时开关，盒子重启后必然关闭。**远程维护请用 SSH（8022）**，并让它随 Termux:Boot 自启。

## 2. 现场诊断（三个视角）

### 盒子侧（Termux）
```bash
ifconfig wlan0                      # 看 UP / inet IP
ping -c 2 192.168.1.1               # 通不通网关（关键）
getprop dhcp.wlan0.ipaddress        # 有没有 DHCP 地址
sv status hass sshd                 # 服务是否在跑
tail -n 20 ~/boot.log               # 本次开机自启有没有执行
```

### 路由器侧
- 终端/客户端列表：找盒子 MAC（本项目盒子 Wi-Fi MAC 以 `7C:88:99` 开头），看**在不在线、IP、连接方式、信号**；
- 如果有两台网关：分别登录，确认**只有一台开 DHCP**、两台 LAN IP 不同。

### 电脑侧
```powershell
ipconfig | findstr /i "IPv4"
arp -a | findstr 192.168.1.
```
确认电脑和盒子在同一网段，且能 `ping` 通网关。

## 3. 修复

### 3.1 盒子“假在线”（接口正常但网关不通）
1. 盒子设置 → 网络 → 该 WiFi → **忽略/忘记网络**；
2. 重新选择 WiFi、**重新输入密码**连接；
3. 回 Termux：`ping -c 2 192.168.1.1` 确认通；
4. 再 `sv up hass`（和 `sv up sshd`）。

> 小米盒子设置路径：设置（齿轮）→ 网络和互联网 / 网络设置 → 无线网络 → 选中 WiFi → 忽略网络。

### 3.2 两台网关同名 WiFi
按影响从小到大选一个：
1. **调低 MESH 漫游阈值**（如 RSSI 从 -65/-60 调到 -75/-70），减少设备来回切；
2. **第二台改有线回程 / AP 模式**，关闭它的 DHCP，LAN IP 改成不同地址（如 192.168.1.2）；
3. 若第二台不需要覆盖：**只关第二台的 WiFi**（同名同密码，其他设备会自动连回主网关，无需重配）；
4. 不推荐直接改 SSID——所有 IoT 设备都要重新配网。

### 3.3 重启后不自启
1. 手动恢复（1 分钟）：
   ```bash
   cd ~ && bash ~/start-ha-env.sh    # 或：sv up hass; sv up sshd
   ```
2. 打开一次 **Termux:Boot**（白色说明页是正常的，它没有设置界面）；
3. 盒子设置里找 **快速启动 / 待机 / 电源** 选项，尽量关闭“快速启动”，让它真正冷启动（冷启动才会发开机广播）；
4. 找不到系统自启管理也别纠结：这是电视盒子固件限制，接受“断电重启后手动开一次 Termux”即可。

### 3.4 长期最稳
- 给盒子加 **USB 网卡走有线**（避免 Wi-Fi 漫游/假死）；
- 给盒子加 **UPS / 不断电**，减少断电重启；
- 路由器给盒子 **DHCP 静态绑定**（有的天翼网关简版固件没有此入口，可在盒子 Wi-Fi 设置里手动填静态 IP）。

## 4. 预防清单

- [ ] 家里只保留 **一个 DHCP 服务器**；
- [ ] 多网关时 WiFi 名尽量区分，或改成 Mesh/AP 正确组网；
- [ ] 盒子 Wi-Fi 出现异常，先“忘记网络→重连”，不要急着重装 HA；
- [ ] 记住手动恢复两条命令：`sv up hass` / `sv up sshd`；
- [ ] 断电重启后先看 `~/boot.log` 有没有记录，再判断是自启问题还是网络问题；
- [ ] 长期建议有线接入（USB 网卡）。

## 5. 一句话总结

> 盒子“消失”九成是 **Wi-Fi/路由器层**的问题（同名多网关、假在线、配置残留），不是 HA 代码；
> 重启后起不来是 **Termux:Boot 没触发**，手动 `sv up hass` 即可恢复。先分清这两类，再动手。
