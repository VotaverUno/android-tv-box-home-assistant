# 家电控制与语音排错（一篇看懂）

> 这篇文档把「洗衣机/洗碗机怎么在 HA 里控制」和「小爱怎么语音触发」合成一条清晰路径。
> 从零开始看：**第 1 章知道谁控制谁 → 第 2 章做虚拟开关 → 第 3 章巴法同步 → 第 4 章按设备配置 → 第 5 章排错**。
> 文档中设备 ID/IP 全部是占位符（`YOUR_DEVICE_ID`），请替换成你自己的。

---

## 1. 先看懂：谁控制谁

```
你说："小爱同学，打开内裤洗"
        ↓
小爱同学 → 米家 App（看到"内裤洗"这个开关）
        ↓
巴法云（把开关状态转给 Home Assistant）
        ↓
Home Assistant（开关被打开 → 执行同名脚本）
        ↓
脚本 → 洗衣机（设程序、开烘干、启动）
```

**为什么要有"虚拟开关"？**
巴法云只支持**开关/传感器/空调/窗帘**这类实体，**不支持脚本和下拉框**。
所以我们在 HA 里造 4 个"假开关"，打开它就执行对应脚本——小爱只认开关，任务就完成了。

---

## 2. 第一步：在 HA 里建 4 个虚拟开关

> 注意：HA 2026 已不支持旧写法 `switch: - platform: template`，必须用下面的 `template:` 写法。

在 `configuration.yaml` 末尾追加：

```yaml
template:
  - switch:
      - name: 内裤洗
        unique_id: xiaoi_underwear
        state: "{{ false }}"
        turn_on:
          - action: script.d9_wash_underwear
        turn_off:
          - delay: "00:00:01"
      - name: 袜子洗
        unique_id: xiaoi_socks
        state: "{{ false }}"
        turn_on:
          - action: script.d9_wash_socks
        turn_off:
          - delay: "00:00:01"
      - name: 洗碗机标准
        unique_id: xiaoi_dishwasher_standard
        state: "{{ false }}"
        turn_on:
          - action: script.dishwasher_standard_start
        turn_off:
          - delay: "00:00:01"
      - name: 海尔智慧洗
        unique_id: xiaoi_haier_smart
        state: "{{ false }}"
        turn_on:
          - action: script.haier_smart_wash
        turn_off:
          - delay: "00:00:01"
```

保存 → 检查配置 → 重启 HA。
重启后会出现 4 个开关：`switch.nei_ku_xi`（内裤洗）、`switch.wa_zi_xi`（袜子洗）、`switch.xi_wan_ji_biao_zhun`（洗碗机标准）、`switch.hai_er_zhi_hui_xi`（海尔智慧洗）。

---

## 3. 第二步：巴法云同步（只勾这些）

HA → 设置 → 设备与服务 → **Bemfa Cloud** → 配置 → 选择要同步的实体：

| ✅ 要勾 | ❌ 不要勾 |
|---|---|
| **内裤洗、袜子洗、洗碗机标准、海尔智慧洗**（4 个虚拟开关） | 所有脚本（"…启动/继续/按模式…"） |
| 正常设备的功能开关（如洗衣机开关、童锁、客厅空调） | 离线/连不上的设备 |
| 需要的传感器（如门状态） | 下拉选择类实体 |

提交后：米家 → 我的 → 其他平台设备 → 巴法 → **解绑后重新绑定**。
设备名要短（巴法云有名字长度限制），这样小爱识别率高。

## 4. 第三步：三台设备怎么配（含踩坑）

### 4.1 美的 D9 小洗衣机（双筒）

| 项目 | 值 |
|---|---|
| 内裤（左筒） | 云程序 **156** |
| 袜子（右筒） | 云程序 **148** |
| 烘干开关 | `0x06` 记录：`1`=开 |
| 启动 | `0x02` 记录：`1` |
| 筒位 | `0x32` 记录：`1`=左、`2`=右 |

**最重要的坑**：D9 是 TLV 协议，**筒位必须和程序/烘干/启动写在同一条命令里**，否则程序会落到默认筒（右边）：

| 目的 | 命令（hex） |
|---|---|
| 左筒 + 内裤 | `db 32 01 01 04 01 9c` |
| 左筒 + 烘干开 | `db 32 01 01 06 01 01` |
| 左筒 + 启动 | `db 32 01 01 02 01 01` |
| 右筒 + 袜子 | `db 32 01 02 04 01 94` |

**顺序**：设程序 → **再**开烘干（设程序会重置烘干）→ 启动。

脚本已封装：`script.d9_wash_underwear`、`script.d9_wash_socks`（已实测通过“小爱→正确筒+程序+烘干”）。

### 4.2 海尔滚筒洗衣机

- 程序是下拉框（132 项，选"智慧洗"）；
- **坑**：设备在**关机状态**下会忽略程序写入；程序写入也是异步的。
- **正确顺序**：保持开机 → 设程序 → **等状态变成"智慧洗"** → 再启动。

脚本：`script.haier_smart_program_only`（只选程序，不启动）、`script.haier_smart_wash`（一键智慧洗，已实测通过）。

### 4.3 美的洗碗机（E1）

- 程序用本地枚举（`standard_wash`/`eco_wash`/`strong_wash`…），选模式即启动；
- 脚本：`script.dishwasher_standard_start`（一键 Standard）；
- **限制**：App 里的"自定义烘干时长"（`dry_set_min`）在本地协议里**只读**，HA 改不了；如需烘干预设请选含烘干的程序（洗烘/单烘干）。

## 5. 排错：现象 → 原因 → 解决

| 现象 | 最可能原因 | 解决 |
|---|---|---|
| 小爱说"没有这个设备" | 巴法没同步/米家没重绑 | 按第 3 章重新勾选 + 米家解绑重绑 |
| 小爱打开了开关，但机器没动 | 脚本报错/设备离线 | HA 里看脚本执行记录 + 设备状态 |
| 启动了错误的程序（如单脱水） | 程序写入被忽略，直接启动了旧程序 | 海尔：按 4.2 顺序；D9：按 4.1 组合筒位 |
| 内裤洗跑到右筒 | D9 只写了程序没写筒位 | 用组合命令（第 4.1 节） |
| 程序对了但没有烘干 | 设程序把烘干重置了 | 顺序改为"程序 → 烘干 → 启动" |
| 下拉框选了没反应 | 设备在运行中被云端忽略 | 先停机/待机再设 |
| 设备一直 unavailable | token 失效/型号不支持局域网 | 见第 6 章 |

**排查工具**：
1. HA → 开发者工具 → 动作 → `logger.set_level` 打开 `midealan` / `custom_components.haier` 的 debug；
2. 看 `~/ha.log` 里的 `Status update`（设备回报）和 `errNo`（云端返回）；
3. 用 `midea_ac_lan.send_command` 逐条发 TLV 记录验证；
4. 改配置前先备份，失败可回滚。

## 6. 换个型号怎么办（方法论）

**不要照抄本页参数**，不同型号字段完全不同，按这 5 步做：

1. 确认集成支持该设备类型（有没有实体生成）；
2. 开 debug 日志，在厂商 App 上操作一次（选程序/开烘干/切筒），从 `Status update` 抓原始值；
3. 用参数指纹确认程序（如"内裤=40 分/3 次漂洗"）；
4. 用 `send_command` **一次只写一个字段**，发完读回验证；
5. 最后才测"启动"；把结果记录成表。

> 本项目 3 台美的（两款空调 + 热水器）就是反例：**云端能取 token，但 LAN 认证失败**——型号不支持本地控制，已禁用。**能取到 token ≠ 能本地控制**。
