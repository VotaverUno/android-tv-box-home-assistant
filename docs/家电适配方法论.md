# 家电适配方法论（不同型号怎么适配）

> 适用：想在 HA 里控制"程序/参数"（不只是开关），但不同品牌、不同型号、不同固件的字段完全不一样。
> 本文用**本项目实测的三台机器**作为例子，给出可复用的排查方法。**不要照抄参数**，要按方法自己抓。

---

## 0. 一句话规律

> **同一品牌同一协议 ≠ 同一字段表。**
> 程序是"枚举/云程序 ID"、烘干是"独立标志位"、左右筒是"location 记录"——每个都要在**你的设备**上实测确认。

---

## 1. 先判断"集成支不支持"（不要一上来就逆向）

| 检查项 | 怎么做 |
|---|---|
| 设备类型是否被支持 | 看 `midea_ac_lan` 的 `midea_devices.py` 里有没有你的 DeviceType 块 |
| 是否有实体生成 | HA → 设备与服务 → 该设备：有实体但只有开关/传感器，说明"能力没暴露" |
| 底层库有没有写方法 | 看 `midealan/devices/<type>/__init__.py` 的 `set_attribute` 分支 |
| 有没有通用服务 | 集成是否提供 `midea_ac_lan.send_command`（本项目有，可发原始 TLV） |

如果底层库连 `set_attribute` 都没有 → 大概率只能走云（App），HA 本地控制没戏。

---

## 2. 抓"程序 ID / 字段值"的标准流程

1. **临时开调试日志**（HA → 开发者工具 → 动作：`logger.set_level`，传 `{"midealan": "debug"}`；不要重启）；
2. 在**厂商 App** 上做一次真实操作（选程序、改烘干、切筒），**不要启动机器**；
3. 看 `~/ha.log` 里的 `Status update: {...}` 行，记录：
   - 程序字段（如 `db_program` 的数值）
   - 关联参数（漂洗次数 `db_rinse_count`、温度、剩余时间 `db_remain_time`）
   - 位置字段（`db_location`）
4. 用"参数指纹"确认它是哪个 App 程序（例：内裤 40 分/3 次漂洗；袜子 28 分/2 次漂洗）；
5. 关闭调试日志（`logger.set_level` 回 `warning`）。

> 本项目实测：小洗衣机的"内裤/袜子"是**云程序**（ID 156/148），不在本地 78 个枚举里——所以光看枚举找不到。

---

## 3. 写字段的标准流程（一次只改一个）

通用做法：`midea_ac_lan.send_command`，`cmd_type=2`（set），`cmd_body` = **桶标识 + TLV 记录**：

```
cmd_body = <bucket> <type> <len> <value...>
例：db 04 01 9c   → 程序 = 0x9c(156)
    db 06 01 01   → 烘干 = 开
    db 32 01 02   → 筒位 = 2
    db 02 01 01   → 启动
```

**纪律**：
1. 每次只发一条记录；
2. 发完立即查状态（或等一条 `Status update`）；
3. 和基线对比，确认改了哪一项；
4. 异常（设备报错/无响应）就停，不要连续发；
5. **永远最后测"启动"**（前 4 步都在待机状态验证）。

---

## 4. 本项目三台机器的实测结论（示例，不是通用）

### 4.1 美的 D9（小洗衣机，双筒）

| 项目 | 结论 |
|---|---|
| 程序 | 云程序：内裤=156、袜子=148（本地枚举里没有） |
| 烘干 | `0x06` 记录，写 1 开、0 关；**顺序：程序→烘干→启动**（设程序会重置烘干） |
| 筒位 | `db_location` 1/2；`0x32` 记录可写筒位（但设程序通常会自动切筒） |
| 启动 | `0x02` 记录 = 1 |
| 验证指纹 | 内裤 40 分/3 次漂洗；袜子 28 分/2 次漂洗；烘干 +161 分 |

### 4.2 美的 E1（洗碗机）

| 项目 | 结论 |
|---|---|
| 程序 | 本地枚举（`standard_wash`/`eco_wash`/`strong_wash`…），`mode_select` 选中即启动 |
| 烘干时长 | `dry_set_min` **只读**——E1 的 `MessageWork` 没有该字节；App 是云端下发的 |
| 替代 | 选含烘干程序（`wash_dry`/`single_dry`），自定义时长仍在 App 设 |

### 4.3 海尔（滚筒洗衣机）

| 项目 | 结论 |
|---|---|
| 程序 | `select` 实体，132 项（云属性） |
| 启动/暂停 | `select.runningmode` 启动/暂停 |
| 参数 | 水温 `number`、转速 `number` |
| 功能开关 | 39 个 switch（抖散/新风/童锁/自动投放…）独立可用 |

## 5. 适配新设备时，按这个清单填表

```
型号：
设备类型/子类型：
协议版本：
程序来源：本地枚举 / 云程序 ID（列出 ID↔App 名称）
程序设置记录：0x?? = 程序
烘干/参数记录：0x?? = 开/关（顺序要求？）
位置/筒位记录：0x?? = 1/2（含义？）
启动/暂停记录：0x02 = 1/0
启动前提：门关、通电、放水？
实测验证：读完状态截图/日志
```

---

## 6. 别踩的坑

- 不同固件字段表可能不同，升级后要复测；
- "设程序"可能**重置**其它参数（如烘干），顺序要试；
- 云程序 ID 不固定（账号/地区/固件可能变），要以实测为准；
- 有的型号**根本不支持局域网控制**，token 拿到了也连不上（本项目三台美的就是这种情况：token/key 云端能取，LAN 认证仍失败）；
- 巴法云/小爱只能同步开关类，程序控制要用"虚拟开关 → HA 脚本"桥接。
