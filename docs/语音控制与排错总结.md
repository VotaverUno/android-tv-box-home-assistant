# 语音控制与排错总结（实战经验）

> 目标：让小爱同学控制"程序级"操作（内裤洗/袜子洗/洗碗机标准/海尔智慧洗），并记录踩过的坑与排查方法。
> 本文所有设备 ID / IP / 账号均用占位符，**不含任何真实敏感信息**。

---

## 1. 整体链路

```
小爱同学
  → 米家（巴法云设备）
  → 巴法云（虚拟开关）
  → Home Assistant（模板开关 → 脚本）
  → 设备（局域网协议 / 厂商云）
```

**为什么需要虚拟开关**：巴法云只支持 **switch / sensor / binary_sensor / climate / cover / light / fan / water_heater** 等实体；`script` 和 `select` 无法同步。所以用"模板开关"当语音触发器，打开时执行脚本。

## 2. 三个高频坑（都踩过并已修复）

### 坑 1：HA 2026 不再支持旧式模板开关

**错误写法**（不生效）：

```yaml
switch:
  - platform: template
    switches:
      xxx: ...
```

HA 日志：`Configuring the template integration under the switch platform key is not supported`

**正确写法**：

```yaml
template:
  - switch:
      - name: 内裤洗
        state: "{{ false }}"
        turn_on:
          - action: script.d9_wash_underwear
        turn_off:
          - delay: "00:00:01"
```

### 坑 2：海尔"设程序"被忽略，结果启动了旧程序

**现象**：想跑"智慧洗"，结果启动了"单脱水"。

**原因**：
- 设备在**关机状态**下会忽略云端的程序写入；
- 程序写入是**异步**的，若紧接着"启动"，会以旧程序启动。

**正确顺序**（实测通过）：

```yaml
- switch.turn_on          # 保持开机
- delay: 2s
- select.select_option    # 统一程序设定 = 智慧洗
- wait_template: "{{ is_state('select.YOUR_HAIER_DEVICE_ID_unifiedprogramsettings', '智慧洗') }}"
  timeout: 20s
  continue_on_timeout: true
- delay: 2s
- select.select_option    # 运行状态 = 启动
```

### 坑 3：美的双筒"设程序"落到错误筒

**现象**：选"内裤洗"，实际启动的是右边筒。

**原因**：D9 是 TLV 协议，**只写程序不写筒位**时，设备落到默认筒。

**正确做法**：筒位和程序/烘干/启动**放在同一条记录**里发送：

| 目的 | TLV 记录（示例） |
|---|---|
| 左筒 + 内裤(156) | `db 32 01 01 04 01 9c` |
| 左筒 + 烘干开 | `db 32 01 01 06 01 01` |
| 左筒 + 启动 | `db 32 01 01 02 01 01` |
| 右筒 + 袜子(148) | `db 32 01 02 04 01 94` |

记录含义：`0x32`=筒位、`0x04`=程序、`0x06`=烘干、`0x02`=启动。

> 顺序注意：设程序会**重置烘干**，所以必须先设程序、再开烘干、最后启动。

## 3. 巴法云同步清单（要/不要）

| 要同步 | 不要同步 |
|---|---|
| ✅ 4 个虚拟开关（内裤洗/袜子洗/洗碗机标准/海尔智慧洗） | ❌ 所有 `script`（巴法不支持） |
| ✅ 正常设备的功能开关/传感器 | ❌ 离线/连不上的设备 |
| | ❌ 只在 App 里用的程序选择实体 |

同步后在米家"其他平台设备 → 巴法"里解绑重绑，设备名要和虚拟开关名一致（名字短，小爱识别率高）。

## 4. 排错工具箱

| 工具 | 用途 |
|---|---|
| `logger.set_level`（HA 动作） | 临时打开 `midealan` / `custom_components.haier` 调试日志，抓 `Status update` |
| `midea_ac_lan.send_command` | 发原始 TLV 记录，逐条验证程序/烘干/筒位 |
| `~/ha.log` | 设备状态回报、云端命令返回（`errNo`） |
| App/面板截图 | 确认"设备实际显示"与"HA 认为"是否一致 |
| 备份快照 | 改配置前先备份，失败一键回滚 |

**排查顺序建议**：
1. HA 里的实体状态是否刷新（`select`/`switch` 值）；
2. 开 debug 看设备是否回报命令成功（`errNo=0`）；
3. 若成功但行为不对 → 检查"筒位/程序/烘干"是否分开发送；
4. 若失败 → 看是否关机状态、是否等待确认、云端是否限流；
5. 最后才考虑"型号不支持"（如本项目 3 台美的：token 可取但 LAN 认证失败）。

---

## 5. 美的三台失败案例（结论）

- 云端登录成功、token/key 都取到了（method 1/2）；
- 但设备局域网认证始终失败（probe false）；
- 判断：该型号（KFR-35G/KS2 空调、JSQ30-MK6 热水器）**不支持本地局域网控制**；
- 处理：禁用条目，停止重试日志；不影响其他设备。

> 经验：**"能取到 token" ≠ "能本地控制"**。适配前先确认型号是否支持 LAN。

---

## 6. 安全注意

- 仓库里不要放：设备 ID、IP、MAC、账号、密码、token、巴法 UID；
- 文档示例统一用 `YOUR_DEVICE_ID` / `YOUR_HAIER_DEVICE_ID` 等占位符；
- 调试日志里出现设备 ID 时，截图/外发前先打码；
- 语音开关名不要包含个人信息（如人名、门牌号）。
